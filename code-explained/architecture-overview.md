## 1. System topology (the moving parts)

            ┌─────────────────────────────┘          │          └──────────────────────┐
            │                                         │                                 │

   │  FRONTEND        │  /test_results       │  STRATO API :8090 │  llm_question   │ GLOBAL API :8020   │
   │  React + Vite    │ ───────────────────► │  test runner +    │ ──────────────► │ scheduler (the     │
   │  (config + dash) │ ◄─────────────────── │  workload driver  │ ◄────────────── │ "brain")           │

## 2. One request, end to end (the main trace)

Follow a single LLM question from a click to the model and back. The **`X-Trace-Id`** header is
generated by Strato and re-read at each hop, so all logs for this question correlate.

```
FRONTEND  submitData.handleSubmit ── POST /start_test ──►  (starts the whole run; see §5)
                                                            then the workload drives questions:

STRATO   run_workload.py  (background thread, asyncio loop)
  │  generate_workload() → [t0,t1,…]            ← schedule (steady/peaks, fixed seed)
  │  for each ts: sleep until ts, then:
  │     trace_id = uuid4();  X-Trace-Id set     ★ trace id BORN here
  │     log_sent()  → LogSent row (feeds RPS)
  │     POST /handle_llm_question ───────────────────────────────┐
  └───────────────────────────────────────────────────────────┐ │
                                                                │ ▼
GLOBAL   routes → handle_llm_request(question, trace_id)        │  ★ trace id re-read (header)
  │  config = config_store.get()                                │
  │  simulated_time = compute_simulated_now(...)                │  ← maps now → simulated moment
  │  recent latencies (read_model_logs) → avg per cluster       │
  │  for each cluster: get_cluster_runtime_data(...)            │  ← PV, carbon, price, load (§4)
  │  cluster = choose_cluster(...)        ★ YOUR scoring        │  score = wc·carbon+we·cost+wl·lat
  │  POST chosen cluster /handle_llm_request ───────────────┐   │
  └───────────────────────────────────────────────────────┐│   │
                                                           ▼▼   │
CLUSTER  routes → handle_llm(question, trace_id)                │  ★ trace id re-read again
  │  with worker_lock:                                          │
  │     choose_worker_node(...)   ← idle-first, slot-aware      │  (concentrates load on purpose)
  │     inflight += 1                                           │
  │  cluster_queue_time_ms = (time so far)                      │  ┐ the latency
  │  POST llama-server /completion ───────────┐                 │  │ decomposition
  │  cluster_llama_inference_ms = (call time) │                 │  ┘ (queue vs inference)
  └──────────────────────────────────────────┐│                │
                                              ▼▼                │
                                    ┌──────────────────┐        │
                                    │ llama-server pod │  ← THE MODEL (bottom of the stack)
                                    │  Qwen2.5-1.5B    │        │
                                    └────────┬─────────┘        │
                                              │ answer JSON     │
        ◄─────────────────────────────────────┘                │
  CLUSTER  finally: inflight -= 1 (never leak a slot); return LLMResponse{answer, slots, timings}
        ◄──────────────────────────────────────────────────────┘
  GLOBAL   parse LLMResponse; log_request() → RequestLog (end-to-end + queue + inference times); return
        ◄──────────────────────────────────────────────────────
  STRATO   record result; (retry only pre-arrival connection failures; no double-count of telemetry)
```

**Three latencies are recorded per request** (this is the heart of your latency story):
- `global_total_time_ms` = **end-to-end** (Strato→…→answer, measured at global).
- `cluster_queue_time_ms` = wait/selection time on the cluster.
- `cluster_llama_inference_ms` = **inference** time (the model itself).

## 3. The power-scheduler loop (your second component)

A background loop in the global API, started at `/start_test`. Every `timeout_s` it decides
**how many** nodes the fleet needs and tells clusters to **execute**. Decision (global) and
execution (cluster) are split.

```
GLOBAL power_scheduler_loop()  (asyncio, on its own thread)
  every timeout_s:
  │
  │  ── TURN ON ─────────────────────────────────────────────────────────────────
  │   score & rank clusters (greenest first)            ← reuses scoring  ★ COUPLING
  │   λ  = get_current_rps()         (count LogSent / window, fleet-wide)
  │   μ  = 1000 / avg_llama_latency  (INFERENCE)         ← throughput, report-consistent
  │   N_throughput = ⌈λ/μ⌉ − N_active
  │   N_latency    = ⌈N_active · (L_obs / L_max)⌉ − N_active   ← S=L_obs/L_max (eq 10)
  │                                   (L_obs fed = INFERENCE  ★ issue #2: report says end-to-end)
  │   N_add = max(N_throughput, N_latency)               ← MAX not sum (no double-count)
  │   distribute N_add to clusters greenest-first ──► POST cluster /turn_on_nodes
  │                                                         │
  │  ── TURN OFF ────────────────────────────────────────  │  ──────────────────
  │   if avg END-TO-END latency > SLO: skip whole pass     │  ← global guard
  │   else ──► POST cluster /turn_off_idle_nodes            │
  │                                                         ▼
  └──────────────────────────────────────────┐   CLUSTER power_scheduler.py (executes)
   stop when config.power_scheduler.start =   │     turn ON:  select OFF nodes →
   False  (set by /stop_test)                 │       ThreadPool: GPIO pulse (gpioset)
                                              │        → wait_for_nodes_to_be_ready (pod + /props)
                                              │     turn OFF: keeper (nodes[0]) never off;
                                              │        skip if inflight>0; idle>threshold →
                                              │        turn_off_node: 10s re-check → SSH sudo shutdown
                                              ▼
                                   ┌─────────────────────────────┐
                                   │  GPIO pin ──optocoupler──►   │  power button (ON)
                                   │  SSH  ── sudo shutdown ──►    │  graceful (OFF)
                                   └─────────────────────────────┘
```

**The coupling in one line:** the same scorer that *routes* each request also decides *where
capacity grows*, so traffic and nodes concentrate on the same (e.g. greenest) cluster.

## 4. Where the scoring numbers come from (data sourcing)

`get_cluster_runtime_data` assembles one `ClusterRuntimeData` per cluster; `score_cluster`
consumes it.

```
get_cluster_runtime_data(cluster, simulated_time, energy, avg_latency)
  │
  ├─ market_data_store (cache, keyed by zone+hour)         reset() on each /start_test
  │     ├─ get_power  ─┬─ DK  → dk_energy (real CROM microgrid, Tailscale)  → P_renewable
  │     │              └─ else → pv_power CSV (capacity factor × 1500 W)     → P_renewable
  │     ├─ get_carbon → Electricity Maps (direct factors, gCO2/kWh)         → grid carbon
  │     └─ get_price  → Electricity Maps (day-ahead, EUR/MWh → /1000 /kWh)  → grid price
  │
  ├─ GET cluster /get_cluster_working_nodes → count WORKING/IDLE
  │     └─ compute_cluster_load(active, idle, energy × power_scale_factor)  → P_load
  │
  └─ (+ DK base load via dk_energy consumption)
        │
        ▼
   ClusterRuntimeData{ renewable_output_w, cluster_load_w, grid_carbon, grid_price, avg_latency, all_off }
        │
        ▼  score_cluster():
   f_grid = max(0, 1 − P_renewable/P_load)            ← microgrid blending
   blended_carbon = grid_carbon × f_grid              blended_cost = grid_price × f_grid
   norm(x) = max(0, 1 − x/ref_max)   (fixed maxima: 670 gCO2, 0.30 €, 12000 ms)
   score = wc·norm(carbon) + we·norm(cost) + wl·norm(latency)     → highest wins
```

## 5. Run lifecycle (start → run → stop)

```
FRONTEND  POST /start_test (Config JSON)
   │
STRATO start_test():  validate via global /validate_config → flip test_running (lock)
   │   → spawn "test-runner" THREAD → return 200 immediately
   │
   └─ run_test (thread):
        set_current_config_id; save_config → DB
        POST global /start_test  ──►  GLOBAL start_test():
        │                               start_time_real = now
        │                               market_data_store.reset()   ← clears stale cache
        │                               config_store.set(config)
        │                               push /set_config to each cluster → build_worker_nodes (K8s)
        │                               ensure_nodes_ready
        │                               if power_scheduler.start: spawn power loop THREAD (§3)
        │
        run_workload(...)  ← drives questions until duration ends OR stop  (§2)
        │     polls should_stop_test() every 0.5s
        finally: _stop_global_test → global /stop_test
                                       └─ config_store.stop_power_scheduler() (start=False → loop exits)
   │
STRATO finally: reset flags (test_running=False) → idle again
   │
FRONTEND polls /test_status → sees idle → redirect to /dashboard?config_id=…
                                            → GET /test_results → charts
```

`STOP` path: frontend `/stop_test` → Strato sets `stop_requested` (workload loop notices, cancels
tasks) → tells global to stop the power loop. Lifecycle states: **idle → running → stopping**.

## 6. Concurrency models (three of them, on purpose)

```
THREADS            ── Strato: 1 background "test-runner" thread so /start_test returns fast.
(OS-scheduled)        Global: 1 "power-scheduler" thread. Cluster: ThreadPool to power on nodes
                      in parallel. Shared state guarded by Locks (test_state_lock, worker_lock, …).

ASYNCIO            ── run_workload: ONE thread runs hundreds of in-flight HTTP requests via the
(cooperative,         event loop (each request is I/O-bound = mostly waiting). power_scheduler_loop
single-thread)        is also async.

THREADPOOL         ── cluster change_node_status("on"): each board takes seconds to boot, so power
(parallel I/O)        them on concurrently; power-OFF is sequential.
```

Rule of thumb: **threads** to get off the request path, **asyncio** to fan out many waits on one
thread, **threadpool** to parallelize slow independent power-ons.

## 7. Persistence & logging (everything lands in 2 tables)

```
configs   ── one row per saved Config (the whole config as JSON)         ← save_config

app_logs  ── one generic row per log, distinguished by log_type:
   ├─ RequestLog        (per request: cluster, node, end-to-end/queue/inference ms, carbon, cost…)
   ├─ LogSent           (per dispatch: used to compute RPS / λ)
   ├─ NodeStatusLog     (per node state change: IDLE/WORKING/OFF → powers the dashboard timeline)
   ├─ MarketSnapshotLog (hourly carbon/price per cluster, deduped)
   └─ "info"/"warning"/… (terminal logs, if SAVE_LOGS_IN_DB)

   keyed by config_id  → that's how one run's data is grouped.
   logger.py tags every line with the active config_id (per process).
```

The dashboard reads aggregated `RequestLog` + `NodeStatusLog` (via `/test_results`) to draw
latency, gCO2, cost, cluster distribution, the service-time breakdown, and the node timeline.

---

## 8. The whole thing in one sentence

> The frontend starts a test on Strato, which replays a **fixed-seed** workload in **simulated
> time** against the global **scheduler**, which scores clusters on **blended carbon/cost/latency**
> and routes each question to the best one while a coupled **power scheduler** scales nodes on the
> same ranking (GPIO on, SSH off), the cluster picks a slot-aware node and calls the **llama**
> model, and every hop is logged to Postgres under one `config_id` for the dashboard to chart.
